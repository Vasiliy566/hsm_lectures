# Как отправить домашку через Planerverse

Здесь вы регистрируете участие в coding agents contest и отправляете репозиторий агента на проверку. Отдельный аккаунт на Planerverse создавать не нужно: на [странице участия](https://planerverse.ru/participate#submit) есть открытая форма заявки.

**Дедлайн: 29 октября 2026, 23:59 МСК.** Все агенты на стенде используют **DeepSeek V4.1 Flash, thinking high**. Временный API-ключ предоставляет стенд; покупать или вставлять свой ключ в форму не нужно. Основной прогон после отбора включает 30 задач SWE-bench. [Правила и технический контракт](https://planerverse.ru/participant-agents.md).

## Шаг 1 Подготовьте агента

Возьмите содержимое `homework_02_agent/` из архива либо доработайте свой агент. Открытый исходный проект использовать можно, но нужны собственные изменения.

В заготовке уже есть четыре инструмента: `list_files`, `search_code`, `read_file`, `replace_in_file`. Реализуйте инструкции и цикл «запрос модели, вызовы инструментов, результаты, новый запрос». Сохраняйте историю на стороне своей программы, сопоставляйте вызовы и результаты по `call_id`, ограничьте число шагов и общее время.

Для текущего демо обработайте также `status == "incomplete"` и `incomplete_details`. Для Chat Completions аналогичный случай обозначается `finish_reason == "length"`. Не разбирайте пустой или оборванный ответ как завершённый JSON и не выполняйте неполные аргументы вызова. Ограничьте повторные попытки; уменьшайте ненужный контекст и размер запрашиваемого фрагмента. Инструкцию платформы можно передать целиком своему coding-агенту. [Контракт запуска и ограничения](https://planerverse.ru/participant-agents.md).

Для своей интеграции следуйте её протоколу обработки неполных ответов: нельзя просто дописать произвольный `function_call_output` без соответствующего полного вызова. Не уменьшайте контекст так, чтобы потерять связь уже сохранённых вызовов и результатов.

## Шаг 2 Создайте публичный GitHub репозиторий

Если аккаунта GitHub ещё нет, зарегистрируйте его на [GitHub](https://github.com/signup). Создайте репозиторий с видимостью **Public**. Код можно загрузить через GitHub Desktop, git или веб-интерфейс GitHub. В веб-интерфейсе используйте загрузку файлов в репозиторий; сохраняйте структуру папок и не выбирайте настоящие `.env`. Для заготовки курса корень репозитория должен выглядеть так:

```text
agent.json
agent.py
pyproject.toml
uv.lock
README.md
.gitignore
.env.example
local_check/
```

Загружайте содержимое `homework_02_agent/`, а не родительскую папку. Важно: платформа ищет `agent.json` в корне. Для другого стека используйте его lock-файл и согласованный способ запуска.

Перед публикацией проверьте файлы. Не отправляйте настоящие `.env`, API-ключи, токены, приватные данные и логи с секретами. `.env.example` должен содержать только примеры или пустые значения. Если секрет уже попал в коммит, простого удаления файла недостаточно: отзовите ключ и очистите историю перед публикацией.

Сделайте коммит и отправьте его на GitHub. Полный SHA получите командой из папки репозитория:

```bash
git rev-parse HEAD
```

Это строка из 40 шестнадцатеричных символов, а не короткий SHA, имя ветки или ссылка на папку. Проверьте, что именно этот коммит доступен в публичном репозитории. После правок нужен новый коммит, push и новый SHA. [Требования к репозиторию](https://planerverse.ru/participant-agents.md).

## Шаг 3 Проверьте локальный запуск

В заготовке есть локальная проверка:

```bash
uv sync
uv run python local_check/run_check.py
```

Для неё задайте параметры модели согласно `homework_02_agent/README.md`; локальные запросы используют ваши настройки и могут быть платными. Локальная проверка не заменяет новое демо: большой контекст и искусственный незавершённый ответ проверяются на сайте отдельно.

На стенде код агента располагается в `/agent`, задача в `/task/TASK.md`, редактируемый репозиторий в `/testbed`. `entrypoint` в `agent.json` задаётся массивом аргументов, а не shell-строкой. Исправления должны появиться в рабочем репозитории, не только в сообщении агента. Параметры подключения берите из `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`; не зашивайте свои адреса, ключи или другую модель. Не используйте `previous_response_id`, серверную историю и hosted tools. [Техническая инструкция](https://planerverse.ru/participant-agents.md).

## Шаг 4 Пройдите демо

1. Откройте [форму участия](https://planerverse.ru/participate#submit).
2. Введите ссылку на GitHub-репозиторий и полный SHA. Для самого демо имя автора и Telegram не требуются.
3. Нажмите **«Проверить демо · 2 проверки»**.
4. Дождитесь завершения обеих проверок. У них общий лимит около 10 минут плюс проверка результата. Пока идёт демо, сохраняйте эту вкладку открытой.
5. Прочитайте результат и подсказки. Если меняете код, сделайте новый коммит, отправьте его на GitHub, замените SHA в форме и повторите проверку.

Первая проверка использует небольшой Python-проект. Вторая проверяет более крупный контекст и на первом запросе специально возвращает тестовый `incomplete` из-за лимита выходных токенов. Агент должен пережить такой ответ и продолжить работу. Это тест устойчивости, а не признак того, что сайт сломан. Всего разрешено **3 запуска демо за 24 часа на IP**, одновременно только один. Не расходуйте попытки на незакоммиченный или недоступный код. [Как устроено демо](https://planerverse.ru/participant-agents.md).

## Если демо не проходит

| Что видно | Что проверить |
|---|---|
| Репозиторий или коммит недоступен | Public, полный SHA, push нужного коммита, отсутствие опечаток в URL. |
| Не найден `agent.json` или код не запускается | Файлы в корне, валидный JSON, пути в `entrypoint`, чтение `--task-file` и работа в `--workspace`. |
| Нет зависимости | В демо зависимости автоматически не устанавливаются из вашего lock-файла. Сверьте доступное окружение с инструкцией; для заготовки используется `openai==2.26.0`. |
| Ошибка JSON после первого ответа | Сначала проверяйте статус завершения. Не передавайте пустой или обрезанный текст в JSON-парсер. |
| Слишком большой контекст или HTTP 413 | Используйте поиск, чтение фрагментов и ограниченный вывод инструментов. Не повторяйте тот же переполненный запрос бесконечно. |
| Цикл не заканчивается | Лимиты шагов, времени и повторных попыток; условия завершения после ответа без вызовов. |
| Агент написал «исправлено», но изменений нет | Реальные записи в `/testbed`, корректный путь, фактический diff. Итоговый текст не заменяет изменения файлов. |

Окружение демо ограничено: в частности, Python 3.11.5 и `openai==2.26.0`; произвольный Dockerfile не собирается. Lock-файл нужен для воспроизводимости, но не означает, что демо автоматически установит любые зависимости. Перед нестандартным стеком прочитайте полный [перечень ограничений](https://planerverse.ru/participant-agents.md).

## Шаг 5 Отправьте заявку

Заполните поля формы:

| Поле | Что указать |
|---|---|
| Название агента | Понятное название вашего проекта. |
| Автор | Ваше имя. |
| GitHub-репозиторий | Ссылка на публичный репозиторий агента. |
| Полный commit SHA | Те же 40 символов, на которых проверяли финальную версию. |
| Модель и версия | На сайте зафиксирована `deepseek-v4.1-flash`; менять её не нужно. |
| Контакт для согласования | Ваш Telegram, например `@username`. |

Прочитайте согласие на публикацию названия, репозитория и результатов. Контакт для согласования не публикуется. Если согласны, отметьте чекбокс и нажмите **«Отправить на проверку»**. Дождитесь подтверждения отправки и сохраните репозиторий и SHA отправленной версии. [Форма участия](https://planerverse.ru/participate#submit).

Результат демо связывается с заявкой при совпадении репозитория и SHA. Отправляйте её из той же вкладки, в которой запускали проверку. Статус демо хранится с приватным токеном этой вкладки; не передавайте его другим. [Привязка демо к заявке](https://planerverse.ru/participant-agents.md).

**Различайте три результата.** Демо проверяет работоспособность и устойчивость. Заявка фиксирует вашу версию для рассмотрения. Основной SWE-bench-прогон проводится после допуска организатором. Сайт позволяет отправить заявку даже без успешного демо, но критерий домашки из курса — пройти демо; отправка формы сама по себе не означает выполнение задания или получение оценки. [Порядок участия](https://planerverse.ru/participant-agents.md).

## Перед отправкой

- [ ] Публичный репозиторий содержит ваши изменения, корневой `agent.json`, README и lock-файл.
- [ ] Секретов нет ни в файлах, ни в истории коммитов.
- [ ] Коммит отправлен на GitHub; в форме указан его полный SHA.
- [ ] Агент использует инструменты для поиска и чтения фрагментов, не загружает весь репозиторий одним запросом.
- [ ] Есть ограничение шагов, времени и повторных попыток; обработан `incomplete`.
- [ ] Обе проверки демо пройдены на том же SHA, который отправляется в заявке.
- [ ] Telegram указан верно; получено подтверждение отправки формы.
