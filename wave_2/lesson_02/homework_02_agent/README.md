# Домашнее задание 2. Агент с инструментами для AgentScore

Сдаётся на [planerverse.ru](https://planerverse.ru/), как и первое. Платформа запускает агента на задачах из реальных репозиториев (SWE-bench Verified) и оценивает итоговый `git diff`.

**Уровень 2:** агент сам ищет нужный код, читает его по частям и правит точечно. Этого не умел агент уровня 1: он передавал модели весь проект одним запросом и получал файлы целиком. На реальном репозитории такой подход не работает.

## Что уже готово

- `agent.json`, `pyproject.toml` и `uv.lock` (`openai==2.26.0`, как в демо-окружении), `.env.example`.
- В `agent.py` есть четыре инструмента и их исполнение (класс `Workspace`):
  - `list_files` — список файлов;
  - `search_code` — поиск по коду;
  - `read_file` — чтение фрагмента с номерами строк;
  - `replace_in_file` — точечная замена.
- Пути проверяются: читать и писать можно только внутри репозитория и не в `.git`.
- Ошибки инструментов возвращаются модели как результат вызова.
- `local_check/run_check.py` — локальная проверка, похожая на демо платформы.

## Что сделать

1. Создайте публичный репозиторий из этой папки. Можно продолжить репозиторий первого задания: замените `agent.py` и обновите `agent.json`.
2. **TODO 1** — `INSTRUCTIONS`. Опишите порядок работы и правила правки. Хорошая основа — `skills/fix-failing-test/SKILL.md` из практики занятия.
3. **TODO 2** — цикл в `run()`:
   - запрос к модели;
   - вызовы функций;
   - `function_call_output` с тем же `call_id`;
   - следующий запрос.

   Остановка — когда модель больше не просит вызовов, при лимите шагов или при лимите времени. Образец — `common.py` из практики.
4. **TODO 3** — обработайте `status == "incomplete"`. Обновлённое демо специально проверяет этот случай: не разбирайте пустой или оборванный ответ как завершённый JSON, ограничьте повторные попытки и размер контекста.
5. Проверьте агента локально, сделайте коммит и нажмите «Проверить демо» на сайте.

## Правила платформы, которые важны для цикла

- Историю ведёт ваша программа. `previous_response_id` и серверная история запрещены.
- Встроенные инструменты сервиса запрещены, разрешены только ваши функции.
- 600 секунд на задачу и до 4096 выходных токенов на один запрос. Поэтому правка делается по частям, а не записью файла целиком.
- Модель на платформе — `deepseek-v4.1-flash`, локально — ваша модель OpenAI. Не включайте `strict` в описаниях инструментов, пока не проверите, что его поддерживает модель платформы.
- Точные правила — в инструкции на сайте. Если она расходится с этим текстом, верна инструкция.

## Локальная проверка

```bash
uv sync
cp .env.example .env            # впишите свой ключ OpenAI
uv run python local_check/run_check.py
```

Агент печатает шаги в stderr: какой инструмент вызван и что вернул. Если агент ходит по кругу, прочитайте эти шаги. Обычно помогает правило в `INSTRUCTIONS` или более понятное описание инструмента.

## Критерии

- Демо на сайте пройдено.
- Пройдены обе проверки обновлённого демо, включая большой контекст и тестовый `incomplete`.
- В логе видно, что агент нашёл файл через инструменты, а не получил весь проект во входе.
- Цикл останавливается сам: при ответе без вызовов, при лимите шагов или при лимите времени.

## Вариант Б (дополнительно): skill для своей задачи

Этот вариант для тех, кто хочет применить готового агента к своей работе, а не писать нового. Он не заменяет демо на платформе.

1. Сделайте папку `my-skill/` со своим `SKILL.md`. Шаблон — `skill_template/` из практики. Можно добавить `references/`.
2. Проверьте формат: `python skills_lab.py --dir <папка со skill>`.
3. Подключите skill к агенту, который поддерживает Agent Skills (Codex, Claude Code, Cursor и другие). Как подключить — в документации вашего агента.
4. Запишите три запроса и что произошло с каждым:
   - запрос, на котором skill должен включиться;
   - запрос, на котором skill включаться не должен;
   - запрос, где нужен инструмент или доступ, которого у агента нет.

Сдать: `SKILL.md`, три запроса и короткий отчёт — включился ли skill и что сделал агент.
