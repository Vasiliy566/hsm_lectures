# Что читать и смотреть после второго занятия

Подборка о structured output, инструментах и skills. Начните с трёх руководств ниже; остальные материалы выбирайте под свою задачу. Время чтения — ориентир для указанных разделов, а не длительность видео.

Все ссылки ведут к авторам платформ или организаторам лекций. Тексты на русском, но код и названия API на английском. Документация Claude и GigaChat объясняет общие механизмы: названия полей и методы SDK нельзя механически переносить в Responses API из практики или в шлюз Planerverse.

## Основной маршрут

### 1 Структурированные выходные данные

[Claude Platform Docs на русском](https://platform.claude.com/docs/ru/build-with-claude/structured-outputs). Руководство, ориентир 15–20 минут на основные разделы.

Читайте введение, работу схемы, примеры с Pydantic и ограничения, особенно незавершённый ответ при достижении лимита токенов. Свяжите это с тремя уровнями проверки из практики: JSON, схема, факты. В Claude используется свой API формата ответа; в коде курса — `text.format` и `responses.parse`.

После чтения: объясните, почему схема не доказывает, что указанный моделью файл существует, и почему обрезанный ответ нельзя считать корректным объектом.

### 2 Как работает использование инструментов

[Claude Platform Docs на русском](https://platform.claude.com/docs/ru/agents-and-tools/tool-use/how-tool-use-works). Руководство, ориентир 10–15 минут.

Разберите цикл: описание инструмента, предложение вызова моделью, исполнение клиентской программой, возврат результата и следующий ответ. Сопоставьте его с `04_tool_call.py`. В Claude названия блоков отличаются от `function_call` и `function_call_output` в практике, но разделение ответственности остаётся тем же.

После чтения: нарисуйте два запроса к модели и отметьте место, где выполняется настоящий Python-код. Что получит модель, если программа отклонила вызов?

### 3 Skills в Claude Code

[Расширение Claude с помощью skills](https://code.claude.com/docs/ru/skills). Документация на русском, ориентир 15–20 минут на создание первого skill, frontmatter и вспомогательные файлы.

Посмотрите устройство `SKILL.md`, роль `description`, размещение файлов и загрузку справочных материалов по необходимости. Это полезно для дополнительного варианта домашки. Функции конкретного продукта и дополнительные поля Claude Code не являются универсальным контрактом всех агентов.

После чтения: создайте skill для своей задачи и проверьте три запроса: должен включиться, не должен включиться, не хватает инструмента или доступа. Отделяйте качество инструкции от разрешений среды.

## Если хочется глубже

### 4 Контракт инструмента через JSON Schema

[Описание пользовательских функций, GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/functions/describing-custom-function). Справочник на русском, ориентир 15 минут на описание функции и примеры параметров.

Полезен для проектирования `name`, `description`, `parameters`, обязательных полей и допустимых значений. Сравните хорошее описание аргумента с расплывчатым «любой текст». Специфические поля GigaChat не нужно добавлять в инструменты курса без проверки API.

Попробуйте описать инструмент `search_code`: какие аргументы обязательны, чем ограничить вывод и как объяснить модели, когда поиск лучше чтения целого файла?

### 5 Видео об инструментах и MCP

[Agents Week, лекция 1.2 Tools. MCP, Алёна Зайцева](https://www.youtube.com/live/VctYHtCap3o?si=rDg-oCkYvpw6ITRS). [Страница организаторов с YouTube и ВКонтакте](https://agentsweek.yandex.com/).

Русская речь, презентация на английском. Подходит, если уже понятен базовый tool loop и хочется связать его с подключением внешних систем. MCP здесь дополнительная тема, он не требуется для сдачи домашки. На странице интенсива есть и вводная лекция 1.1, если хочется повторить основы.

Вопрос после просмотра: чем транспорт подключения инструментов отличается от решения модели вызвать конкретную функцию?

### 6 Видео о памяти и ограничениях агента

[Agents Week, лекция 2 Memory and Guardrails in LLM-Powered Agents, Кирилл Мищенко](https://agentsweek.yandex.com/). На странице программы выберите лекцию 2; рядом доступны записи на YouTube и ВКонтакте, а также отдельный семинар 2.

Русская речь, слайды на английском. Этот блок полезен при переходе от маленького учебного проекта к длинной истории и реальным репозиториям. Смотрите после базового цикла, не вместо его реализации.

Практический вопрос: что оставить в истории после чтения длинного файла и как сократить её, не потеряв задачу, ограничения и связь вызовов с результатами?

### 7 Прикладной вебинар с function calling

[Создание Telegram-бота на базе LLM с RAG и Function Calling, Дмитрий Сошников](https://yandex.cloud/ru/events/1117). Запись вебинара Yandex Cloud от 3 апреля 2025; на странице есть встроенное видео и ссылка на YouTube.

Материал на русском для тех, кто хочет увидеть использование внешних систем в другом приложении, а не только coding-агенте. В нём также есть RAG и многоагентное тестирование: для второго занятия это необязательное расширение. Примеры используют сервисы Yandex, а не API домашки.

Вопрос после просмотра: какие действия безопасно разрешать автоматически, а какие требуют проверки аргументов или подтверждения пользователя?

## Как извлечь пользу из одного материала

Выберите одну идею, внесите одно изменение в своего агента и проверьте его на конкретном примере. Запишите ожидаемое поведение, фактические вызовы, результат и ограничение, которое осталось. Описание модели «всё исправлено» не заменяет проверку файлов и тестов.

Для сдачи ориентируйтесь не на примеры чужих платформ, а на [техническую инструкцию Planerverse](https://planerverse.ru/participant-agents.md).
