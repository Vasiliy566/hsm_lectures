# Занятие 1.1. Примеры кода

Код, который преподаватель показывает на занятии. Повторять вместе с ним не обязательно: всё можно запустить потом по этой инструкции. Скрипты работают напрямую с OpenAI через официальный Python SDK и Responses API.

## Установка (10 минут)

1. Python 3.10 или новее: `python --version`.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создайте API-ключ OpenAI (platform.openai.com → API keys) и поставьте на проект лимит расходов.
4. Скопируйте `.env.example` в `.env` и впишите `OPENAI_API_KEY` и `OPENAI_MODEL`. Имя модели назовёт преподаватель.
5. Проверьте: `python 01_first_call.py` печатает ответ, токены и время.

Имена переменных — `OPENAI_API_KEY`, `OPENAI_MODEL` и при необходимости `OPENAI_BASE_URL` — те же, что задаёт платформа домашек.

Ключ храните только в `.env`. Не вставляйте его в код, git, чат, скриншоты и демонстрацию экрана. Если ключ утёк — отзовите его и выпустите новый.

| Ошибка | Что проверить |
|---|---|
| 401 | Ключ; файл `.env` лежит в этой папке |
| 400 / 404 | Имя модели; параметр, который модель не принимает |
| 429 | Баланс, лимит расходов или лимит запросов |
| Connection error | Сеть: доступ к api.openai.com; в `.env` не осталось `OPENAI_BASE_URL` от заглушки |

Проверить установку без ключа можно на офлайн-заглушке: `python offline/fake_llm_server.py`, а в `.env` — `OPENAI_API_KEY=offline`, `OPENAI_BASE_URL=http://127.0.0.1:8765/v1`, `OPENAI_MODEL=offline`. Заглушка отвечает заранее записанными ответами — это не модель.

## Показ 1. Первый запрос, токены и история

```bash
python 01_first_call.py
python 01_first_call.py "What is a token?"
python 01b_chat_history.py
```

- В выводе: ответ, статус, токены входа и выхода (и отдельно токены рассуждения), время. Ответ сохраняется в `answers.jsonl` вместе с условиями запуска.
- Задайте тот же вопрос по-русски и по-английски и сравните `input_tokens`.
- В `01b_chat_history.py` задайте вопрос, потом «а подробнее?». Число входных токенов растёт: программа каждый раз отправляет всю историю. Закомментируйте строку `history.append({"role": "assistant", ...})` — модель перестанет понимать, о чём речь.

## Показ 2. Один промпт — несколько запусков

```bash
python 02_same_prompt.py
python 02_same_prompt.py --prompt "Сколько будет 17 * 23? Ответь только числом."
python 02_same_prompt.py --effort high
python 02_same_prompt.py --temperature 0      # если модель принимает параметр
```

Скрипт отправляет один и тот же промпт несколько раз и считает, сколько получилось разных ответов. Сравните творческую задачу и задачу с одним верным ответом, а также время и токены рассуждения при разном `--effort`.

## Показ 3. Два промпта на одних и тех же примерах

```bash
python 03_compare_prompts.py prompts/vague.txt prompts/full.txt --runs 3
```

Модель пишет функцию `parse_duration`: строка вроде `"1h 30m"` → число секунд. Для каждого промпта несколько запусков. Код каждого запуска сохраняется в `runs/`, а `check_duration.py` проверяет его на 12 примерах:

| Должна вернуть число | | Должна вызвать ValueError |
|---|---|---|
| `"45s"` → 45 | `"1h 30m 15s"` → 5415 | `""` |
| `"15m"` → 900 | `"90m"` → 5400 | `"10"` |
| `"2h"` → 7200 | `"2H"` → 7200 | `"1.5h"` |
| `"1h30m"` → 5400 | | `"30m1h"`, `"1h1h"` |

**Критическая ошибка** — плохой вход молча превратился в число (например, `"10"` → 10). Итог дописывается в `results.csv`; цена считается по `PRICE_IN_PER_M` и `PRICE_OUT_PER_M` из `.env`.

Код в `runs/` написала модель, и скрипт его исполняет — в отдельном процессе с ограничением по времени. Прежде чем запускать чужой код, его стоит прочитать.

## Термины занятия

| Термин | Коротко |
|---|---|
| LLM | Модель, которая продолжает текст по одному токену |
| Токен | Кусок текста; единица входа, выхода и цены |
| Контекст, окно контекста | Всё, что модель видит в одном запросе; предел токенов на запрос |
| Роли | `instructions` (system) — правила, `user` — задача, `assistant` — прошлые ответы |
| Обучение и использование | Меняем веса модели / меняем только вход |
| Галлюцинация | Правдоподобный, но неверный ответ |
| Сэмплирование | Случайный выбор токена по вероятностям |
| Temperature | Насколько часто выбираются менее вероятные токены |
| Reasoning | Промежуточные рассуждения модели до ответа |
| Промпт | Задача, правила, примеры и формат ответа |
| Zero-shot, few-shot | Без примеров / с примерами прямо в промпте |
| API, usage | Вызов модели из кода; сколько токенов ушло |
| Tool calling, skill | Модель просит действие у программы; сохранённая инструкция (занятие 1.2) |
