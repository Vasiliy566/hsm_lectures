# Python API workshop

Материал для заключительной части первого урока. Презентация здесь не нужна: преподаватель открывает код и запускает ячейки по очереди.

## Подготовка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` локально. Никогда не отправляйте ключ преподавателю, в чат или в Git.

## Как запускать

Откройте [api_workshop.py](api_workshop.py) в PyCharm или VS Code. Файл размечен ячейками `# %%`.

Не запускайте весь файл целиком: каждая секция делает отдельные API-вызовы.

Рекомендуемый порядок:

1. конфигурация клиента;
2. минимальный Responses API запрос;
3. устройство `response.output`;
4. fallback на Chat Completions;
5. streaming и длинные ответы;
6. Structured Outputs;
7. состояние диалога;
8. обработка ошибок;
9. async batch;
10. tool calling;
11. логирование учебного eval.

## Варианты доступа

Код поддерживает три технические конфигурации без описания способов обхода ограничений:

- официально доступный API;
- корпоративный шлюз;
- локальный или OpenAI-compatible endpoint.

Совместимый endpoint может реализовывать только Chat Completions. В таком случае секции Responses API, Structured Outputs и tool calling могут потребовать адаптации под документацию провайдера.

## Что показать на занятии обязательно

- ключ берётся из окружения;
- `response.output_text` безопаснее жёсткого пути через `output[0]`;
- streaming сокращает воспринимаемое ожидание длинного ответа;
- Pydantic задаёт форму результата;
- правильная схема не гарантирует правильные факты;
- tool call сначала проверяется и выполняется вашим Python-кодом.
